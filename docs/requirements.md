# NAGI 要件定義

## 1. 概要

| 項目 | 内容 |
|---|---|
| サイトの目的 | 自然の中で上質な非日常を過ごせる宿の魅力を伝え、宿泊予約につなげる |
| CV | サイト内の予約フォームからの予約リクエスト |
| ターゲット | 20〜30代の男女。日常から離れて自分を整えたい人（ひとり旅・カップル・友人同士） |
| 運営者 | 架空の宿ブランド「NAGI（凪）」。全国に6施設 |
| コンセプト | 心が凪ぐ場所へ。静けさの中で、何もしない時間を過ごして自分を整える |
| デザイン | ミニマル、余白多め、大きな写真と明朝体、アースカラー |
| 実装 | HTML / CSS / JS（静的）、スマホファースト、レスポンシブ |
| 予約フォーム | 入力 → 確認 → 完了をJSで再現（入力チェック付き。実際の送信はしない） |
| 用途 | ポートフォリオ |

## 3. サイトマップ

```
NAGI
├── TOP
├── CONCEPT
├── STAYS
│   └── STAY DETAIL ×6
├── NEWS
│   └── NEWS DETAIL
├── GUIDE
└── RESERVE
```

独立したページは6つ（TOP／CONCEPT／STAYS／NEWS／GUIDE／RESERVE）、使い回す型は2つ（STAY DETAIL／NEWS DETAIL）。

## 4. URL・ディレクトリ

| ページ | URL |
|---|---|
| TOP | `/` |
| CONCEPT | `/concept/` |
| STAYS | `/stays/` |
| STAY DETAIL | `/stays/{スラッグ}/` |
| NEWS | `/news/` |
| NEWS DETAIL | `/news/{スラッグ}/`（6件。一覧は下の「NEWS／NEWS DETAIL」を参照） |
| GUIDE | `/guide/` |
| RESERVE | `/reserve/`（施設詳細から来たときは `/reserve/?stay={スラッグ}`） |

**ルール**
- 短い小文字の英単語にする。2語以上はハイフンでつなぐ
- 一覧と詳細は親子関係にする
- 各フォルダに `index.html` を置き、URLの末尾は `/` で終える
- 予約の入力・確認・完了は同じURLのまま、JSで画面を切り替える

```
stay/
├── index.html
├── concept/
├── stays/{biei, yatsugatake, asagiri, setouchi, aso, yanbaru}/
├── news/{setouchi-open, winter-sauna-plan, new-year-holidays}/
├── guide/
├── reserve/
├── docs/
└── assets/
    ├── css/style.css
    ├── js/main.js
    └── images/{common, top, concept, stays/各施設, news, guide, reserve}/
```

## 5. 共通セクション

- **ヘッダー**：ロゴ、ナビ（CONCEPT／STAYS／NEWS／GUIDE）、「予約する」ボタン（常に表示）。スクロールしても上部に残る。スマホではナビを三本線のボタンにまとめ、全画面メニューで開く
- **フッター**：ロゴ、連絡先（TEL・MAIL・予約フォームへの案内）、架空のサイトであることの表示、コピーライトと写真のクレジット。PCはロゴを左・連絡先を右の2列
  - 裏方リンク（運営会社／プライバシーポリシー／宿泊約款／特定商取引法に基づく表記／サイトのご利用について）は、架空のサイトで行き先がないため外した（2026-10-22）。予約フォームの同意文の「プライバシーポリシー」もリンクを外し、文字だけにした

- **パンくずリスト**（2026-10-22 追加）：TOPとRESERVE以外の16ページ。写真のFVのすぐ下に小さく置く（NEWS DETAILは記事のタイトルの上）。例：`TOP / 宿一覧 / 北海道・美瑛`。RESERVEは入力に集中してもらうため置かない。長い記事タイトルは、はみ出す分を「…」にする。検索エンジン向けの構造化データ（JSON-LD）は、公開するドメインが決まってから追加する

- **架空のサイトの表示**（2026-10-22 追加。公開に向けて）：全ページのフッターに「このサイトは、Webデザインのポートフォリオとして制作した架空の宿のサイトです。実在の施設・団体とは関係ありません。予約フォームから実際の予約は行われません。」を常に表示する。RESERVEでは入力の前にも「入力した内容はどこにも送信されず、実際の予約も行われません」と表示する
- **検索に出ない設定**：全ページに `<meta name="robots" content="noindex, nofollow">` を入れる（実在の宿と混同されないよう、検索結果に出さない。ポートフォリオはURLを直接渡して見てもらう）

- **公開（Vercel）**（2026-10-22）：`https://stay-roan.vercel.app/`。リンクは相対パスで、URLの末尾が `/` であることを前提にしているため、`vercel.json` に `"trailingSlash": true` を書く（ないと Vercel が `/stays/` を `/stays` に転送し、宿の詳細や記事へのリンクが404になる）。`docs/` と `top/hero.jpg`（原本）は公開しない（`.vercelignore`。ドラッグ＆ドロップでアップするときは、この2つを含めない）

- **表示速度**（2026-10-22、スマホのPageSpeed Insightsが56〜58点だったため）
  - Google Fonts は使っている太さだけにした（Cormorant Garamond 400・500／Noto Sans JP 300・400／Shippori Mincho 400）。表示を止めないよう、`preload` ＋ `media="print" onload` の形であとから読み込む
  - 写真は横幅 750・1080・1500px の小さいサイズ（`〇〇-750.webp` など）も用意し、`srcset` と `sizes` で画面に合うものを選ばせる。FVの写真には `fetchpriority="high"`
  - 手元での Lighthouse（スマホ）：TOP 99／CONCEPT 99／STAYS 91／美瑛 92／NEWS 99／GUIDE 99／RESERVE 97（変更前の公開サイトのTOPは56）

## 6. ページごとの目的とCTA

```
知る ─→ 共感する ─→ 比べる ─→ 決める ─→ 不安を消す ─→ 予約する
TOP      CONCEPT     STAYS     STAY DETAIL   GUIDE         RESERVE
                      ↑
                    NEWS（再訪のきっかけ）
```

| ページ | 目的 | メインのCTA | サブのCTA | ファーストビューで最優先に見せるもの |
|---|---|---|---|---|
| TOP | 世界観を伝え、各ページへ振り分ける | 宿を見る → STAYS | コンセプトを読む → CONCEPT | 写真1枚とキャッチコピー |
| CONCEPT | 「泊まりたい」と共感してもらう | 6つの宿を見る → STAYS | — | 思想を伝える一文 |
| STAYS | 自分に合う宿を見つけてもらう | 詳細を見る → STAY DETAIL | — | 6施設のカードと絞り込み |
| STAY DETAIL | 泊まる宿を決めてもらう（最重要） | この宿を予約する → RESERVE | ご利用案内 → GUIDE | 写真、エリア、タイプ、料金の目安 |
| NEWS | 再訪や予約のきっかけを作る | 記事を読む → NEWS DETAIL | — | 新着のお知らせ |
| NEWS DETAIL | 内容を伝え、関係する宿へつなぐ | 関係する宿を見る → STAY DETAIL | 一覧へ戻る | タイトルと日付 |
| GUIDE | 予約前の不安を消す | 予約する → RESERVE | 宿を見る → STAYS | よくある質問の項目 |
| RESERVE | 迷わず最後まで入力してもらう | 確認画面へ → 予約を確定する | — | ステップ表示と最初の入力欄 |

## 7. ページごとのセクション構成

### TOP（実装済み：`index.html`）
1. メインビジュアル：写真の中央にロゴ、左下にキャッチコピー「心が凪ぐ場所へ。」、右下にSCROLL（日付・時刻は 2026-10-30 に削除）。スクロールすると写真が生成りに溶けていく
2. コンセプト：縦書きの文章（PCでは見出しを左、文章を右に寄せる）→ テキストリンク「コンセプトを読む」
3. STAYSへの入口：見出しを左・説明文を右。宿カード3つ（美瑛・八ヶ岳・瀬戸内、PCでは真ん中を下げる）→ 塗りのボタン「6つの宿を見る」（メインCTA）。スマホではカードを1枚ずつ見せ、写真の左右の三角の矢印かスワイプで切り替える（下に「1 / 3」と何枚目かを表示。宿のページの「ほかの宿」も同じ）
4. GUIDEへの入口：写真を画面の左端まで広げ、右に「はじめての方へ」→ テキストリンク「ご利用案内を見る」
5. NEWS：新着3件（日付・カテゴリー・タイトル）→ テキストリンク「お知らせ一覧へ」
6. 予約への入口：写真が画面に止まったまま上を「静けさに、会いにいく。」が流れ、最後はフッターに覆われる → 枠線のボタン「予約する」

デザインの考え方は [design.md](design.md) を参照。

写真は仮の画像（`assets/images/**/*.svg`）。実際の写真ができたら差し替える。

### CONCEPT（実装済み：`concept/index.html`）
1. 見出しと思想を伝える一文「何もしない、をしに行く。」：写真を全面に置き、白文字を重ねる（ヘッダーは写真の上では透明）。演出はつけない。以前FVにあったリード文は、TOPと並びをそろえたときに外した
2. 「凪」に込めた思い（文章が止まり、周りを写真が流れる）
3. NAGIの3つの約束（自然・静けさ・上質）：一語＋2行程度の短い文章だけにし、2と4の演出の間の静かな区切りにする
4. 4つの過ごし方（サウナ・星空・焚き火・海）→ 該当する宿へ（PCでは場面がめくれる）
5. CTA：6つの宿を見る

内容を詰めすぎると離脱につながるため、「何もしない一日」「泊まった人の言葉」は入れない（2026-10-22 決定）。
4の過ごし方は、STAYSの絞り込み「過ごし方」の選択肢とそろえる。

### STAYS（実装済み：`stays/index.html`）
1. ページタイトルとリード文：CONCEPTとトンマナをそろえ、写真を幅いっぱいに置いて白文字を重ねる。高さは画面の約70%にして、すぐ下の絞り込みが最初の画面にのぞくようにする（2026-10-22 変更）
2. 絞り込み：**過ごし方だけ**（すべて／サウナ／星空／焚き火／海）。1つだけ選べる。URLの `?style=sauna|stars|bonfire|sea` でも指定できる
3. 施設カード×6（北から順）：写真、エリア、ひとことのコピー、タイプ、過ごし方、料金の目安。PCは2列で右の列だけ下げる、スマホは1列
4. CTA：迷ったらご利用案内へ

宿は6つしかなく、3種類の絞り込みを組み合わせると「該当なし」が出やすいため、絞り込みは過ごし方だけにした（2026-10-22 決定）。ターゲットは場所より「どう過ごしたいか」で選ぶと考え、CONCEPTの4つの過ごし方ともそろえた。

### STAY DETAIL（6つすべて実装済み：`stays/{スラッグ}/index.html`。美瑛を型にして中身を差し替えた）
1. FV：写真は画面に止まったまま、上を宿の紹介文が流れ、次のセクションに覆われる。最初の1画面は他ページと同じ並び（中央に宿名、左に縦書きのコピー）で、下に料金の目安と予約ボタン。写真はゆっくり等倍に戻る
2. この宿での過ごし方：時間帯の違う3つの場面（例：午後・夜・朝）。PCでは写真と文章を左右交互に置く

### ファーストビューのルール（2026-10-22 決定、同日に見直し）
- **写真を幅いっぱいに置く**：TOP／CONCEPT／STAYS／STAY DETAIL／NEWS（一覧）／GUIDE。ヘッダーは写真の上では透明にする（共通のスタイル `.page-hero`）
- **文字だけ**：RESERVE（入力に集中してもらうため）、NEWS DETAIL（記事の中に写真があるため）
- 高さはページの目的で変える：CONCEPT・STAY DETAILは全画面（世界観に浸ってほしい）、STAYSは約70%（すぐ下で選んでほしい）、NEWS・GUIDEは約50%（すぐ読んでほしい。`.page-hero--half`）
- 当初はNEWS・GUIDEも文字だけにしていたが、写真のページから移ると急に事務的に見えるため、トンマナをそろえて写真を置いた
- 文字の並びはTOPとそろえる：タイトル（英字＋和文）は画面の中央、コピーはPCでは左に縦書き（書き出しをタイトルの上端にそろえ、2行目以降は少し下げる）、スマホではタイトルの下に横書きで中央揃え。タイトルはTOPのロゴより小さくする（2026-10-22 決定）
